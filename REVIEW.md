# Spartan X — Full Review Panel (38 reviewers)

_Expert gate + matched user per feature/topic (sonnet) · 4 Dragon's Den investors (opus) · 5 competitor-app users (sonnet) · opus synthesis. Grounded in FEATURES.md + 29 screenshots + code. 2026-06-29._


## Fully spec'd? **MOSTLY**  ·  Overall **6/10**


The feature surface is unusually well-specified and the build is far past prototype: 14 feature areas each have a coherent spec, the core loop (Claim -> Practice -> Friction -> Prediction -> 6-step Reflection -> hash-signed Proof -> Standard) is implemented end-to-end, safety interlocks exist, and the honesty conventions (preview chips, no fake stats) are consistently applied. So as a SPEC of what the product is, it is largely complete. But 'fully specced' fails on two counts. First, multiple places where the spec ASSERTS behavior the code does NOT deliver -- these are spec-vs-implementation contradictions, not missing features: the practice timer is a frozen '10:00' string that never counts down; the debrief promises 'you will see how it matched reality at reflection' but never renders prediction-vs-outcome; 'NO REFLECTION. NO STANDARD.' is cosmetic because a blank 6-step submit still moves the standard; the Cloud panel says only 'metrics' are shared but cloudSnapshot() uploads the full reflection ledger; emergency numbers are labelled 'locale-honest' but are hardcoded 112/999/911. A spec that the implementation silently violates is not fully specced -- it is mis-specced. Second, an entire commercial/retention layer is unspecified beyond backlog bullets: no pricing, no account model, no retention loop (no streak, no push, no reminders that fire), and all of Phase B (auth, sync, payments, leaderboards, challenges) is a roadmap, not a spec with acceptance criteria. The recurring vocabulary inconsistency (six domain labels -- Stabilizing/Tested/Under Review/Baseline/HOLD/Forming -- not mapped to the five-rung ladder) is a genuine spec gap flagged independently by three reviewers. And the review infrastructure itself is broken: the e2e harness bleeds prior localStorage state so onboarding shots 01-05 all render the 'RECOVERED FROM BACKUP' error instead of the documented Access/Select/Execute/Report screens -- meaning part of the spec was never actually verifiable against ground-truth pixels.


### Spec gaps

- Spec-vs-code contradictions: timer never counts (frozen 10:00), debrief never shows prediction-vs-outcome, 'No reflection. No standard.' not enforced on blank submit, Cloud claims 'metrics only' but uploads full reflection ledger, 'locale-honest' emergency numbers are hardcoded 112/999/911
- No unified status vocabulary: six domain labels (Stabilizing/Tested/Under Review/Baseline/HOLD/Forming) are not mapped to the five-rung ladder (Untested->Tested->Stabilizing->Baseline->Elevated) -- flagged by Standard, Ethos, and Visual reviewers independently
- No retention spec: no streak, no working reminder/push (reminder window is a passive note; push deferred to Phase B), no account -- the day-2 return mechanism is unspecified
- No monetization spec: zero pricing, paywall, or payment surface; all revenue mechanics are backlog bullets (#20-23) with no acceptance criteria or tested mechanic
- Entire Phase B (auth, sync, leaderboard, challenges, wearable signals) is roadmap, not spec; cloud activation path is a raw '?backend=<url>' dev instruction shown in the real user UI
- Empty-state and gating behaviors underspecified: empty proof ledger renders no CTA; preview modules (Human Review) write real integrity-domain proofs into the ledger with no preview guard
- Broken review harness: shots.js deep-merges prior localStorage so onboarding shots 01-05 are all the backup-error overlay, not the documented onboarding screens -- the onboarding spec is unverifiable against the captured pixels
- Calibration / Cognitive Load module are undeclared orphans: Cognitive Load has no preview kicker, value statement, or live backing despite being non-locked; calibration stat is computed but surfaced nowhere in the primary loop

## Top strengths

- Genuinely principled integrity engineering, repeatedly praised by both experts and competitor users: B4 hash-chained, content-addressed tamper-evident proof ledger with CRDT set-union merge and server re-verification -- real anti-cheat for self-improvement, not theater. A Stoic/Day One paying user said it is the only journaling structure where fabricating a result is architecturally detectable.
- The core behavioral loop is structurally tighter than competitors: the 6-step debrief (Result/Friction/Negotiation/Decision/Lesson/Correction) forces accountability at each node, and the Call It -> outcome prediction-calibration mechanic is a rare, correctly pre-commitment-locked metacognitive feature almost no habit app has.
- Safety system is unusually mature and clinically sound: crisis/self-punishment/restriction flags gate the leaderboard and challenges, RECOVER holds the user even on a good next day to prevent the one-good-day ego-press, pain-downgrade guard with correct Fitts's-law button order, and reframing recovery as discipline not retreat. Praised by the over-training persona and all experts.
- Live readiness command (PRESS/HOLD/SCALE/RECOVER) computed from six calibration sliders + pain selector, with intensity physically disabled in RECOVER -- a recovery-aware gate that Whoop/Garmin recovery scores lack consequence for and that blank-page tools (Stoic, Day One) have no concept of.
- Honesty-by-construction brand and design taste: explicit 'preview / sample data' chips on every unbuilt module, no fabricated stats or testimonials, no dark patterns, cohesive obsidian+bronze visual language that even the design-sensitive and low-vision reviewers found earned rather than cosplay.

## Prioritized gaps


**[P0] 'RECOVERED FROM BACKUP -- stored data was unreadable' banner renders on fresh install / first run, dominating the splash and Access screens**  
Why: Highest-frequency complaint in the whole panel -- independently flagged by the onboarding persona+expert, the ethos persona+expert, and two investors. A brand-new user's first impression is a data-loss error, which is fatal to D1 for a consumer app and poisons the 'prove it to yourself' tone before a single tap. Root cause is the e2e harness deep-merging prior localStorage (restoredFromBackup:true) into onboarding seeds, so it also makes onboarding shots 01-05 unverifiable.  
Action: In shots.js clear localStorage entirely before seeding each onboarding shot (localStorage.clear() then set), regenerate shots 01-05, and confirm the backup banner cannot fire on a genuinely empty first-install state. Fix the underlying restore-detection so it only triggers when a real prior payload existed.

**[P0] On RECOVER, the gold 'CONTINUE STANDARD' / Begin Practice CTA is not disabled or relabeled -- the only gate is inside beginMission, after the tap**  
Why: Behavioral-health risk, not a UX preference. A user in severe-pain or overtraining state sees a high-salience gold button their training reads as 'go hard' directly contradicting the 'Physical intensity disabled' passive text two elements above it; the affordance beats the warning every time.  
Action: When computeReadiness returns RECOVER, relabel the CTA to 'Begin Recovery Practice' and restyle from gold/primary to neutral/steel to break the learned gold=full-press association.

**[P0] Crisis / self-punishment / restriction flags are freely untogglable -- the same one-tap toggle that sets 'Currently in crisis' also removes it, instantly re-enabling leaderboard and challenges**  
Why: Single change with the most direct clinical-harm reduction. A person in acute crisis can lose all protections via a tremor, panic tap, or second-thought with zero friction, contradicting the spec's implication that these protections are forced/permanent.  
Action: For the three mental-health-critical flags, replace toggleArray removal with a confirmation modal requiring an explicit 'I am safe now' acknowledgement plus a cooldown stored in state. Physical flags (injury/pain/medical) stay freely toggleable.

**[P0] No retention or monetization machinery, and the architecture fights both**  
Why: Unanimous across all four investors (all 'out', scores 3-4). No streak, no working push/reminder, no account, no price, 200-entry cap; the only acquisition surface is a plain-text share with ~0 viral coefficient. A private, offline, account-less discipline app only retains people who already have discipline -- a D7/D30 graveyard -- and the 'local-only, nothing leaves your device' promise inverts the very paid-cloud upgrade that would monetize it.  
Action: Before any spend: ship the daily-return loop (opt-in reminders + active-days/streak surfaced as the hook) and a verifiable-proof shareable artifact (image card / hash-verified public Standard page that competitors cannot fake), then run one paid-cloud-sync experiment on a real 1k+ cohort and report D30 retention and conversion. Investors flip on retention+payment data, not more craft.

**[P0] Multiple spec-vs-code contradictions where the app promises behavior it does not deliver**  
Why: Directly answers 'är det fullt speccat?' -- a spec the implementation silently violates is mis-specced and erodes the product's own honesty brand. Concrete cases: frozen '10:00' timer that never counts down (no elapsed/completion signal); debrief never shows the promised prediction-vs-outcome so the calibration loop never closes; 'NO REFLECTION. NO STANDARD.' is cosmetic because a blank 6-step submit still moves the standard; Cloud panel says 'metrics' but uploads the full reflection ledger; 'locale-honest' emergency numbers are hardcoded 112/999/911 and wrong outside three regions (dangerous in an acute crisis).  
Action: Wire beginMission to set executionStartedAt + executionSeconds=600 and call startTimer on a timer node with id=timerValue; add a read-only prediction-vs-outcome step at the start of debrief; gate debrief steps 3/5/6 with a >=4-char check before NEXT; either send a text-stripped metrics-only snapshot or disclose full-ledger upload; detect locale or replace numbers with 'call your local emergency number' + findahelpline link.

**[P1] No unified status vocabulary -- six domain labels are not mapped to the five-rung ladder; standard headline and progress bar use two non-synchronized measurement systems**  
Why: Flagged independently by Standard, Ethos, and Visual reviewers. The Standard screen is the central feedback mechanism; a user cannot place a domain (HOLD/Forming) on the overall ladder, and the headline can claim a rung lower than the bar shows -- the feedback signal contradicts itself, eroding trust.  
Action: Drive the h1 from standardStageIndex() as the single source of truth, and align per-domain labels to the same five-rung vocabulary (or add a visible mapping). Retire the heuristic title in buildStandardSummary() to a subtitle only.

**[P1] Destructive and external actions lack guards: Delete Local Data wipes everything (incl. rollback key) on a single tap with no confirm; deterministic mock auth token 'tok_'+handle allows trivial impersonation; '?backend=<url>' raw dev syntax shown in the real user UI**  
Why: Each violates the project's own frontend/customer standards and the privacy brand. Single-tap irreversible data loss is the highest-probability real-world harm for a solo discipline app; the deterministic token invalidates every leaderboard-honesty guarantee the moment a backend connects; the raw query-param both blocks real users from cloud and is a phishing vector.  
Action: Add a confirm modal naming what is lost before reset; generate a crypto-random token at registration indexed server-side; replace the '?backend=' instruction with a human CTA (Join beta / QR) and require an HTTPS-only consent modal when a ?backend= value differs from stored.

**[P1] Accessibility: no JS focus trap on the 6 modals (keyboard users Tab into the obscured background -- WCAG 2.1 SC 2.1.2 reverse), plus aria-current='false' noise, missing slider ARIA value semantics, and a sub-4.5:1 inactive tab label**  
Why: The low-vision reviewer would use the app but was nearly broken by six identical sliders and indistinguishable toggle states; the focus-trap gap is a concrete standards violation, not a nice-to-have, and aria-modal is not honored for containment in Chrome/Firefox.  
Action: Set inert on #app whenever a modal is open (one-line, zero deps); emit aria-current='step' only on the active step; add aria-valuemin/max/now/valuetext + polite live region to sliders; raise inactive tab color to >=4.6:1; add a visible ON state to safety toggles and distinguish the active slider.


## Investor verdict (Dragon's Den)

All four investors voted out (scores 3-4) with a strikingly unanimous diagnosis: this is the best-engineered, most principled self-discipline app they have seen, and that is precisely why it is currently un-investable. The integrity machinery (hash-chained proof ledger, CRDT sync, safety interlocks) is genuine craft but not a moat -- a vanilla-JS localStorage PWA with one plain-text share button has no data network effect, no distribution lock-in, and is copyable by a funded clone with push notifications in a quarter. Monetization is $0 and structurally fought by the product's own soul: it is free, account-less, offline, and refuses the vanity metrics, streak-loss pressure, and social comparison that normally drive retention and conversion in this niche. Retention machinery is absent (no streak, no working push, no account, no cross-device hook), so the loop only retains people who already have discipline -- the worst consumer segment. The plausible path (freemium paid-cloud sync/leaderboards/challenges) inverts the 'nothing leaves your device' promise that attracts the user in the first place. Every investor named the same flip condition: real cohort data -- ship Phase B and show D30 retention above ~25% plus a paid-cloud conversion above ~5% on 1k+ installs, a sub-6-month CAC channel that is not the share button, and a payment signal (even a pre-sale). Two investors also flagged the 'RECOVERED FROM BACKUP' error as the only first-run screen they could see, calling a broken first 10 seconds fatal to D1.

## Synthesis verdict

Honest answer to 'är det fullt speccat?': mostly, but not fully -- and the gaps are more serious than 'missing features'. The product is feature-rich and the core loop is genuinely well-built and well-specified, but the panel surfaces several places where the spec asserts behavior the code does not deliver (frozen timer, uncloseable calibration loop, unenforced 'No reflection. No standard.', mislabeled cloud data scope, fake 'locale-honest' emergency numbers). A spec the implementation silently violates is mis-specced, and for a product whose entire brand is honesty, that is the most important thing to fix first. Treat the eight P0 items as the gate: kill the fresh-install backup banner (the single most-flagged issue, and its harness root cause), make the RECOVER and crisis-flag safety guards real (the two highest clinical-harm risks), close the spec-vs-code contradictions, and unify the standard vocabulary so the dashboard stops contradicting itself. Separately and equally true: the engineering is ahead of the business by a wide margin. Every investor was unanimous -- the craft is not the missing piece; retention and a payment signal are. The strategic recommendation is a clean split: (1) a short integrity-and-safety hardening pass to make the spec true and the safety system non-bypassable, then (2) a single instrumented retention+monetization experiment (reminder loop, an unfakeable verified-proof shareable artifact, paid cloud sync) on a real cohort. Score 6/10 -- exceptional craft and a defensible philosophical wedge, held back by spec/implementation contradictions, P0 safety bypasses, and the complete absence of a tested retention or revenue mechanic. Fix the safety P0s before anyone uses this for real; prove D30 retention before anyone funds it.

### Accessibility — expert 6/10 (fix-first)
Strengths: Focus restore on full re-render: captureFocusKey/restoreFocus (app.js:555-604) explicitly captures the focused control before the entire #app is wiped and restores it by id/data attribute afterward — a rare and correct solution to the SPA re-render focus-loss problem.; Deliberate :focus-visible ring: styles.css:837-843 defines a 2px amber (#d39b3d) outline at 8:1 contrast on the obsidian background (per the inline comment) and covers every interactive class — buttons, tabbar, pain-options, choice-cards, inputs, selects, textareas, module-list buttons, anchors.; Reduced-motion handled at two layers: CSS transitions are gated behind prefers-reduced-motion: no-preference (styles.css:1201-1208), AND an in-app 'Reduce motion' checkbox in System (shot 50) applies .reduced-motion which strips all transitions/animations with !important — the only PWA that needs to work offline cannot rely on the OS signal alone, so the in-app fallback is genuinely necessary.
